## Module 4: Website Speed Optimization

Speed is not cosmetic — it is a ranking factor and a conversion factor. Every SRS site must target:

- **LCP (Largest Contentful Paint)**: under 2.5 seconds
- **FID / INP (Interaction to Next Paint)**: under 200ms
- **CLS (Cumulative Layout Shift)**: under 0.1
- **PageSpeed Insights score**: 90+ on mobile, 95+ on desktop
- **GTmetrix grade**: A (90+)

### Layer 1 — Hosting & Server Optimization

The fastest code on a slow server is still a slow site. Hosting is the foundation.

**Recommended hosting stack for SRS clients:**

| Traffic Level | Recommended Host | Plan Type |
|--------------|-----------------|-----------|
| New / Small (< 10K visits/mo) | Hostinger Business, SiteGround GrowBig | Shared/Cloud |
| Growing (10K–50K visits/mo) | Cloudways (DigitalOcean), Kinsta | Managed Cloud VPS |
| Established (50K+ visits/mo) | Kinsta, WP Engine, Cloudways (Premium) | Managed Dedicated |

**Server-level optimizations to request/configure:**
```
☐ PHP 8.1+ enabled (check in hosting panel or php.ini)
☐ LiteSpeed or Nginx web server (NOT Apache if possible)
☐ OPcache enabled and configured:
    opcache.enable=1
    opcache.memory_consumption=256
    opcache.max_accelerated_files=10000
    opcache.revalidate_freq=0
☐ Gzip or Brotli compression enabled
☐ HTTP/2 or HTTP/3 enabled (via Cloudflare or host panel)
☐ SSL/TLS: TLS 1.2 minimum, TLS 1.3 preferred
☐ Keep-Alive connections enabled
☐ MySQL query cache enabled (for shared hosting where accessible)
```

**Cloudflare Configuration (mandatory for all SRS sites):**
```
☐ Proxy status: Proxied (orange cloud) for root domain and www
☐ SSL Mode: Full (Strict)
☐ Always Use HTTPS: ON
☐ Auto Minify: HTML + CSS + JS (if not handled by WP Rocket)
☐ Brotli: ON
☐ Caching Level: Standard
☐ Browser Cache TTL: 4 hours (WP Rocket handles longer caching)
☐ Rocket Loader: OFF (conflicts with many WP plugins)
☐ Page Rules: Set cache-everything rule for static pages if needed
☐ Cloudflare Zaraz: Consider for analytics (reduces JS load)
```

### Layer 2 — WP Rocket Configuration (Cache Plugin)

WP Rocket is the SRS standard cache plugin. Configure as follows:

```

  ☐ Cache lifespan: 10 hours

FILE OPTIMIZATION TAB
  ☐ Minify CSS files: ON
  ☐ Combine CSS files: OFF (causes issues with Elementor — leave OFF)
  ☐ Load CSS asynchronously (Remove render-blocking): ON
  ☐ Minify JavaScript files: ON

  ☐ Load JS deferred: ON
  ☐ Delay JavaScript execution: ON
     → Add to delay list: Google Analytics, Facebook Pixel, 
       HotJar, Intercom, chat widgets, non-critical scripts

MEDIA TAB
  ☐ LazyLoad images: ON
  ☐ LazyLoad iframes and videos: ON
  ☐ Add missing image dimensions: ON
  ☐ Disable WordPress embeds: ON (prevents loading oEmbed scripts)
  ☐ WebP caching: ON (if using Imagify/ShortPixel for WebP)
  ☐ Remove unused CSS: TEST carefully — can break Elementor styles

PRELOAD TAB
  ☐ Activate preloading: ON
  ☐ Preload links: ON (prefetches pages on hover)
  ☐ Prefetch DNS requests: Add all third-party domains:
      //fonts.googleapis.com
      //fonts.gstatic.com
      //www.google-analytics.com
      //connect.facebook.net
      //cdn.jsdelivr.net (if used)

  ☐ Never cache: Any page with a logged-in user session
```

### Layer 3 — Image Optimization

Images are almost always the #1 cause of slow load times. Apply these at every level:

**Imagify Configuration:**
```
☐ Compression level: Aggressive (for most sites) or Ultra (test carefully)
☐ Resize larger images: ON — Max width: 1920px, Max height: 1080px
☐ Convert to WebP: ON
☐ Convert to AVIF: ON (if supported by server/browser)
☐ Backup original images: ON
☐ Bulk optimize: Run on all existing library images on first install
☐ Auto-optimize on upload: ON
```

**Image Standards for New Uploads:**

| Image Type | Max File Size | Format | Max Dimensions |
|-----------|--------------|--------|---------------|
| Hero/banner | 150KB (after compression) | WebP | 1920×1080px |
| Blog featured image | 80KB | WebP | 1200×628px |
| Product image | 100KB | WebP | 1000×1000px |
| Logo | 20KB | SVG (preferred) or PNG | As designed |
| Gallery image | 120KB | WebP | 1200×900px |
| Background texture | 50KB | WebP | 1920×600px |

**Native HTML/WordPress image best practices:**
```html
<!-- Always declare width and height to prevent CLS -->
<img src="image.webp" width="800" height="450" 
     alt="Descriptive alt text with keyword where natural" 
     loading="lazy" decoding="async">

<!-- Above-the-fold hero image: never lazy load -->
<img src="hero.webp" width="1920" height="1080" 
     alt="Hero description" 
     fetchpriority="high">
```

**Alt Text Standards:**
- Every image must have a descriptive alt text
- Include the target page keyword naturally where it fits — don't force it
- Decorative images (icons, dividers): use `alt=""`
- Never keyword-stuff alt text: `alt="plumber london plumbing service london cheap plumber"` → wrong

### Layer 4 — Core Web Vitals Specific Fixes

**LCP (Largest Contentful Paint) — Common Causes & Fixes:**
```
CAUSE: Hero image loading slowly
FIX: Preload the hero image via <link rel="preload"> in <head>
     Add to Rank Math's header scripts or theme functions.php:
     <link rel="preload" as="image" href="/wp-content/uploads/hero.webp">

CAUSE: Render-blocking CSS/JS above the fold
FIX: WP Rocket → Remove render-blocking resources + defer JS

CAUSE: Slow server response (TTFB over 600ms)
FIX: Enable full-page caching, upgrade hosting, enable OPcache

CAUSE: Large DOM size (over 1500 nodes)
FIX: Simplify Elementor layouts, remove unused sections/widgets
```

**CLS (Cumulative Layout Shift) — Common Causes & Fixes:**
```
CAUSE: Images without width/height attributes
FIX: Always declare width and height on every <img> tag

CAUSE: Ads, embeds, or iframes loading without reserved space
FIX: Set CSS aspect-ratio on containers before content loads

CAUSE: Web fonts causing FOIT/FOUT (text shifting)
FIX: Add font-display: swap to @font-face declarations
     Preload critical font files via <link rel="preload">

CAUSE: Dynamic content injected above existing content
FIX: Reserve space for banners/notices using min-height
```

**INP (Interaction to Next Paint) — Common Causes & Fixes:**
```
CAUSE: Heavy JavaScript blocking the main thread
FIX: Delay non-critical JS using WP Rocket's delay feature
     Defer all third-party scripts (chat, analytics, ads)

CAUSE: Long tasks in JS execution
FIX: Identify with Chrome DevTools → Performance tab
     Break long tasks using setTimeout or requestIdleCallback

CAUSE: Too many event listeners on scroll
FIX: Use passive event listeners: addEventListener('scroll', fn, {passive: true})
```

## Module 5: The SRS Digital Asset — Build Standards

Every website built by SRS is a **Digital Asset** — structured to be understood and cited by AI systems, search engines, and machine learning algorithms, while performing for human visitors.

### The 5 Pillars of an SRS Digital Asset

#### Pillar 1 — Semantic HTML Structure
Machine readability starts with clean HTML. Every page must use the correct semantic elements:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <!-- Critical meta first -->
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Primary Keyword | Brand Name</title>
  <meta name="description" content="150–160 char description with keyword and CTA">
  
  <!-- Preconnect for performance -->
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
  
  <!-- Canonical -->
  <link rel="canonical" href="https://yourdomain.com/page-url/">
</head>
<body>
  <header role="banner">
    <nav role="navigation" aria-label="Main navigation">
      <!-- Navigation -->
    </nav>
  </header>

  <main role="main">
    <article> <!-- For blog posts -->
      <h1>One H1 Per Page — Exact or Near-Match to Target Keyword</h1>
      <section>
        <h2>Section Heading (Keyword Variation)</h2>
        <p>Content...</p>
      </section>
    </article>
  </main>

  <aside role="complementary"> <!-- Sidebar if applicable -->
  </aside>

  <footer role="contentinfo">
    <!-- Footer -->
  </footer>
</body>
</html>
```

**HTML Non-Negotiables:**
- One `<h1>` per page — always
- Heading hierarchy: H1 → H2 → H3 (never skip levels)
- All interactive elements must be keyboard-accessible (`<button>`, `<a>` with href, not `<div onclick>`)
- `lang` attribute on `<html>` element (critical for multilingual + screen readers)
- `alt` text on every meaningful image

#### Pillar 2 — Schema Markup (JSON-LD)
Every SRS site must have structured data that tells AI systems exactly what the business is. Implemented via Rank Math or custom JSON-LD in `<head>`.

**Homepage — Organization Schema:**
```json
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Client Business Name",
  "url": "https://www.clientdomain.com",
  "logo": "https://www.clientdomain.com/logo.png",
  "description": "2–3 sentence business description using primary keywords",
  "foundingDate": "YYYY",
  "contactPoint": {
    "@type": "ContactPoint",
    "telephone": "+1-XXX-XXX-XXXX",
    "contactType": "customer service",
    "availableLanguage": "English"
  },
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "123 Business St",
    "addressLocality": "City",
    "addressRegion": "State",
    "postalCode": "XXXXX",
    "addressCountry": "US"
  },
  "sameAs": [
    "https://www.facebook.com/clientpage",
    "https://www.instagram.com/clienthandle",
    "https://www.linkedin.com/company/clientname",
    "https://twitter.com/clienthandle"
  ]
}
```

**Service Pages — Service Schema:**
```json
{
  "@context": "https://schema.org",
  "@type": "Service",
  "serviceType": "Service Name",
  "provider": {
    "@type": "Organization",
    "name": "Client Business Name"
  },
  "description": "Description of the service using target keywords",
  "areaServed": {
    "@type": "City",
    "name": "Target City"
  },
  "hasOfferCatalog": {
    "@type": "OfferCatalog",
    "name": "Service Catalog"
  }
}
```

#### Pillar 3 — Technical SEO Foundations (Dev Responsibilities)

```
robots.txt (CRITICAL — configure before launch):
  User-agent: *
  Allow: /
  Disallow: /wp-admin/
  Disallow: /wp-login.php
  Disallow: /cart/
  Disallow: /checkout/
  Disallow: /thank-you/
  Sitemap: https://www.yourdomain.com/sitemap_index.xml

  # Allow AI crawlers (SRS GEO requirement):
  User-agent: GPTBot
  Allow: /
  User-agent: CCBot
  Allow: /
  User-agent: anthropic-ai
  Allow: /
  User-agent: Google-Extended
  Allow: /

.htaccess performance additions (Apache/LiteSpeed):
  # Enable Gzip
  <IfModule mod_deflate.c>
    AddOutputFilterByType DEFLATE text/html text/plain text/xml
    AddOutputFilterByType DEFLATE text/css application/javascript
    AddOutputFilterByType DEFLATE application/json application/xml
  </IfModule>

  # Browser caching
  <IfModule mod_expires.c>
    ExpiresActive On
    ExpiresByType image/webp "access plus 1 year"
    ExpiresByType image/png "access plus 1 year"
    ExpiresByType image/jpg "access plus 1 year"
    ExpiresByType text/css "access plus 1 month"
    ExpiresByType application/javascript "access plus 1 month"
  </IfModule>

  # Force HTTPS
  RewriteEngine On
  RewriteCond %{HTTPS} off
  RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
```

#### Pillar 4 — Mobile-First Development

Every SRS website is built mobile-first. Test at these breakpoints in Elementor:

| Breakpoint | Width | Priority |
|-----------|-------|---------|
| Mobile | 375px–767px | **Highest** — Google indexes mobile first |
| Tablet | 768px–1024px | Medium |
| Desktop | 1025px–1440px | Standard |
| Wide | 1441px+ | Enhancement only |

**Elementor responsive rules:**
- Set mobile font sizes: H1 28–36px, H2 22–28px, Body 16px minimum
- Hide decorative elements on mobile (not content)
- Stack columns: desktop 2-col → mobile single col
- Tap targets minimum 44×44px (buttons, links, nav items)
- Test with real device or Chrome DevTools at 375px width before client review

```
☐ Google Tag Manager (if multiple tracking codes needed)

☐ Facebook Pixel (if running Meta ads)
```

## Module 6: WordPress Homepage Design Process

The homepage is built in two stages: **wireframe/layout approval**, then **full design implementation**.

### Stage 1 — Homepage Layout Sections (Standard SRS Template)

Build every SRS homepage with these sections in this order (customize per client):

```
SECTION 1: HERO
  - Full-width, above the fold
  - H1 headline (primary keyword + value proposition)
  - Subheadline (supporting benefit statement)
  - Primary CTA button + Secondary CTA (e.g., "Get Started" + "Learn More")
  - Hero image or background (from Graphic Designer)
  - Trust badges or "As seen in" logos (if available)

SECTION 2: SOCIAL PROOF BAR
  - Client logos or review platform badges
  - High-contrast, light background
  - Builds immediate trust

SECTION 3: ABOUT / VALUE PROPOSITION
  - Who is the business and what do they solve?
  - 2–3 key differentiators with icons
  - Supporting image (team, office, product)

SECTION 4: SERVICES OVERVIEW
  - Grid or card layout: 3–6 service tiles
  - Each tile: icon + service name + 1-line description + "Learn More" link
  - Each tile links to its dedicated service page

SECTION 5: HOW IT WORKS (Process Section)
  - 3–5 step numbered process
  - Removes friction and builds confidence

SECTION 6: FEATURED TESTIMONIALS / CASE STUDIES
  - 2–3 client testimonials with name, company, photo
  - Or: featured case study card with result metrics

SECTION 7: BLOG / RESOURCES PREVIEW
  - Latest 3 blog posts (auto-pulled via Elementor Posts widget)
  - Supports content freshness signals for SEO

SECTION 8: CTA SECTION (CONVERSION BLOCK)
  - Bold, high-contrast background (brand primary color)
  - Strong headline: "Ready to [Desired Outcome]?"
  - Single CTA button
  - Phone number or email for direct contact

SECTION 9: FOOTER
  - Logo + tagline
  - Quick links: Services, About, Blog, Contact, Legal
  - Contact info (NAP consistent with Google Business Profile)
  - Social media icons
  - Copyright + Privacy Policy + Terms links
```
